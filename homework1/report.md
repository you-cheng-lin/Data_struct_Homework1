# 作業一：阿克曼函數、冪集

## 申論及開發報告

### 阿克曼函數

本題使用遞迴方式實作阿克曼函數，並另外使用陣列模擬 Stack，將遞迴流程改為非遞迴方式。

阿克曼函數具有非常快速的成長特性，因此可以觀察遞迴演算法在輸入增加時對效能造成的影響。

### 冪集

Powerset 是求一個集合所有可能子集合的集合。

如果集合有 `n` 個元素，每一個元素都有選擇或不選擇兩種可能，因此共有：

```math
2^n
```

個子集合。

### 心得討論

透過阿克曼函數與 Powerset 的實作，我發現不同複雜度的演算法，在資料量增加時，所需的執行時間也會以不同的速度成長。

實際測試後，可以更明顯地看出演算法複雜度對執行效率的影響。

另外也學會使用 `chrono` 進行程式效能量測。

## 解題說明

### 阿克曼函數

阿克曼函數定義如下：

```math
A(m,n)=
\begin{cases}
n+1, & m=0 \\
A(m-1,1), & m>0,\ n=0 \\
A(m-1,A(m,n-1)), & m>0,\ n>0
\end{cases}
```

程式依照以上三種情況進行判斷。

以 `A(1,2)` 為例：

```math
A(1,2)=A(0,A(1,1))
```

```math
A(1,1)=A(0,A(1,0))
```

```math
A(1,0)=A(0,1)=2
```

因此：

```math
A(1,1)=A(0,2)=3
```

最後：

```math
A(1,2)=A(0,3)=4
```

所以：

```math
A(1,2)=4
```

### 冪集

對於集合中的每一個元素，都有兩種選擇：

1. 不加入目前子集合。
2. 加入目前子集合。

因此 `n` 個元素會產生：

```math
2^n
```

個子集合。

例如：

```math
S=\{a,b,c\}
```

則共有：

```math
2^3=8
```

個子集合。

## 效能分析

### 阿克曼函數

#### 時間複雜度

其遞迴關係為：

```math
T(0,n)=O(1)
```

```math
T(m,0)=T(m-1,1)+O(1)
```

```math
T(m,n)=T(m,n-1)+T(m-1,A(m,n-1))+O(1)
```

因此阿克曼函數的計算量會快速成長。

#### 空間複雜度

由於遞迴需要使用系統 Stack，因此若以 `D(m,n)` 表示最大遞迴深度：

```math
O(D(m,n))
```

### 阿克曼函數－非遞迴實作

雖然改用陣列模擬 Stack，不再使用系統函式遞迴，但仍然需要執行與原本遞迴流程相同的運算。

時間複雜度可表示為：

```math
O(T(m,n))
```

陣列大小固定為 `10000`，因此程式配置的空間為：

```math
O(10000)=O(1)
```

但若考慮實際 Stack 使用量，其空間需求與最大 Stack 深度有關。

### 冪集

每個元素都有兩種選擇，因此共有：

```math
2^n
```

個子集合。

如果只考慮產生子集合的遞迴結構：

```math
O(2^n)
```

但是程式還需要將每個子集合中的元素輸出。

每個子集合最多包含 `n` 個元素，因此完整時間複雜度為：

```math
O(n2^n)
```

空間方面，`current[]` 最多儲存 `n` 個元素，遞迴深度也為 `n`，因此：

```math
O(n)
```

## 程式實作

### 阿克曼函數－遞迴實作

```cpp
#include <iostream>
using namespace std;

int Ackermann(int m, int n)
{
    if (m == 0)
        return n + 1;

    else if (n == 0)
        return Ackermann(m - 1, 1);

    else
        return Ackermann(m - 1, Ackermann(m, n - 1));
}

int main()
{
    int m, n;
    cin >> m >> n;

    if (m < 0 || n < 0)
    {
        cout << "Error: m and n must be Natural numbers." << endl;
        return 1;
    }

    cout << Ackermann(m, n) << endl;

    return 0;
}
```

### 阿克曼函數－非遞迴實作

```cpp
#include <iostream>
using namespace std;

int a(int m, int n)
{
    int x[10000];
    int top = -1;

    x[++top] = m;

    while (top >= 0)
    {
        m = x[top--];

        if (m == 0)
            n++;
        else if (n == 0)
        {
            n = 1;
            x[++top] = m - 1;
        }
        else
        {
            n--;
            x[++top] = m - 1;
            x[++top] = m;
        }
    }

    return n;
}

int main()
{
    int m, n;

    cin >> m >> n;

    cout << a(m, n) << endl;

    return 0;
}
```

### 冪集

```cpp
#include <iostream>
using namespace std;

void powerset(char S[], int n, int index, char current[], int size)
{
    if (index == n)
    {
        cout << "{ ";

        for (int i = 0; i < size; i++)
            cout << current[i] << " ";

        cout << "}" << endl;
        return;
    }

    powerset(S, n, index + 1, current, size);

    current[size] = S[index];
    powerset(S, n, index + 1, current, size + 1);
}

int main()
{
    char S[] = {'a', 'b', 'c'};
    char current[3];

    powerset(S, 3, 0, current, 0);

    return 0;
}
```

### 效能量測（Measuring）

#### 阿克曼函數

##### 量測方法

使用 C++ `chrono` 測量 `Ackermann()` 實際執行時間。

為了避免單次量測受到系統背景工作影響，可以進行多次測量並取平均值。

```cpp
#include <chrono>

auto start = chrono::high_resolution_clock::now();

int result = Ackermann(m, n);

auto end = chrono::high_resolution_clock::now();

auto duration =
    chrono::duration_cast<chrono::microseconds>(end - start);

cout << duration.count() << " us" << endl;
```

##### 實際測試結果

> 以下數據必須使用自己的電腦實際執行後填入，不使用預設或估計數值。

| 測試案例 | m | n | 輸出結果 | 實際執行時間 |
|---|---:|---:|---:|---:|
| 一 | 0 | 10 | 11 | 待實測 |
| 二 | 1 | 10 | 12 | 待實測 |
| 三 | 2 | 5 | 13 | 待實測 |
| 四 | 3 | 3 | 61 | 待實測 |

##### 量測結果分析

隨著輸入參數增加，阿克曼函數需要進行的遞迴呼叫會快速增加，因此執行時間也會增加。

實際執行時間會受到 CPU、編譯器最佳化、作業系統背景工作等因素影響，因此以實際 `chrono` 測量結果為準。

#### 冪集

##### 量測方法

使用不同大小的集合測量 `powerset()` 的執行時間。

##### 實際測試結果

| 測試案例 | n | 子集合數量 | 實際執行時間 |
|---|---:|---:|---:|
| 一 | 5 | 32 | 待實測 |
| 二 | 10 | 1024 | 待實測 |
| 三 | 15 | 32768 | 待實測 |
| 四 | 20 | 1048576 | 待實測 |

子集合數量由：

```math
2^n
```

計算。

##### 量測結果分析

當 `n` 增加時，Powerset 的子集合數量以指數方式增加。

例如：

```math
2^5=32
```

```math
2^{10}=1024
```

```math
2^{20}=1048576
```

因此可以觀察到輸入規模增加後，程式的執行量會快速增加。

由於程式還需要輸出每個子集合，因此實際執行時間也會受到輸出成本影響。
