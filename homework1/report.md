## 一、阿克曼函數

### 1. 解題說明

本題要求我們使用遞迴的方式實作阿克曼函數。

我們發現到阿克曼函數在 `n=0` 以及 `n` 與 `m` 皆不為 `0` 的情況下都有自我呼叫的做法。

於是乎在這種條件下，我們只需要寫出一個遞迴函式實作即可。

阿克曼函數的定義如下：

```math
A(m,n)=
\begin{cases}
n+1, & m=0 \\
A(m-1,1), & m>0,\ n=0 \\
A(m-1,A(m,n-1)), & m>0,\ n>0
\end{cases}
```

#### 1.1 範例

以 `A(1,2)` 為例：

```math
A(1,2)=A(0,A(1,1))
```

```math id="2utd9c"
A(1,1)=A(0,A(1,0))
```

```math id="1os8wk"
A(1,0)=A(0,1)=2
```

```math id="qj5xub"
A(1,1)=A(0,2)=3
```

```math id="uq5b8q"
A(1,2)=A(0,3)=4
```

所以：

```math id="0zsq8d"
A(1,2)=4
```

這個例子可以看出，Ackermann 函數會將前一次遞迴的結果當作下一次函式的參數，因此會產生巢狀遞迴。

---

### 2. Algorithm Design & Programming

本題的函數規則便是程式的演算法。因此我們只需要依照規則寫出演算法即可。

1. 如果 `m = 0`，回傳 `n + 1`。
2. 如果 `m > 0` 且 `n = 0`，計算 `A(m - 1, 1)`。
3. 如果 `m > 0` 且 `n > 0`，先計算 `A(m, n - 1)`，再將結果代入 `A(m - 1, A(m, n - 1))`。

```cpp
#include <iostream>
using namespace std;

int Ackermann(int m, int n)
{
    if (m == 0) // when m=0, just n + 1
        return n + 1;

    else if (n == 0) // when m>0 and n=0, reduce m by 1 and set n to 1
        return Ackermann(m - 1, 1);

    else // when m>0 and n>0, first calculate Ackermann(m,n-1), then use the result
        return Ackermann(m - 1, Ackermann(m, n - 1));
}

int main()
{
    int m, n;
    cout << "Enter m and n: ";
    cin >> m >> n;
    if (m < 0 || n < 0) {
        cout << "Error: m and n must be Natural numbers." << endl;
        return 1;
    }

    cout << Ackermann(m, n) << endl;

    return 0;
}
```

### 3. 效能分析 (Analysis)

#### 3.1 時間複雜度（Time Complexity）

阿克曼函數的遞迴結構非常特殊，因此無法像一般的迴圈或遞迴演算法一樣，方便地化簡成 `O(n)`、`O(n^2)` 等簡單的多項式時間複雜度。

其遞迴關係為：

```math
T(0,n)=O(1)
```

```math id="o2x8f4"
T(m,0)=T(m-1,1)+O(1)
```

```math id="1iz5fu"
T(m,n)=T(m,n-1)+T(m-1,A(m,n-1))+O(1)
```

所以本程式的時間複雜度具有非常快速的 Ackermann 等級成長。

#### 3.2 空間複雜度（Space Complexity）

由於程式使用遞迴，因此需要使用系統的遞迴呼叫堆疊。

若以 `D(m,n)` 表示執行過程中的最大遞迴深度，則空間複雜度為：

```math
O(D(m,n))
```

## 阿克曼函數－非遞迴實作

### 解題說明

阿克曼函數原本可以使用遞迴方式實作，但由於遞迴會使用系統的 Stack 儲存函式呼叫資訊，因此可以使用陣列自行模擬 Stack，將原本的遞迴流程改成迴圈執行。

程式使用 `x[10000]` 作為 Stack，並使用 `top` 紀錄 Stack 頂端的位置。

當 `m = 0` 時，相當於：

```math
A(0,n)=n+1
```

因此直接將 `n` 加 1。

當 `n = 0` 時，相當於：

```math
A(m,0)=A(m-1,1)
```

因此將 `n` 設為 1，並將 `m-1` 放入 Stack。

其他情況則相當於：

```math
A(m,n)=A(m-1,A(m,n-1))
```

先將 `n` 減 1，並依序將 `m-1` 與 `m` 放入 Stack，以模擬原本的遞迴呼叫。

### 程式實作

```cpp
#include <iostream>
using namespace std;

int a(int m, int n)
{
    int x[10000];
    int top = 0;

    x[top++] = m; //stack push m 

    while (top >= 0)
    {
        m = x[top--]; //stack pop m

        if (m == 0)
            n++;
        else if (n == 0)
        {
            n = 1;
            x[top++] = m - 1; //stack push m - 1
        }
        else
        {
            n--; 
            x[top++] = m - 1; //stack push m - 1
            x[top++] = m; //stack push m
        }
    }

    return n;
}

int main()
{
    int m, n;

    cin >> m >> n;

    cout << a(m, n) << endl;

    return 0;
}
```

### 測試與驗證

以：

```text
輸入：
1 2
```

阿克曼函數計算：

```math
A(1,2)=4
```

因此程式輸出：

```text
輸出：
4
```

結果與阿克曼函數的定義相符。

### 複雜度分析

阿克曼函數本身的成長速度非常快，因此其時間複雜度也會快速增加。

使用 Stack 模擬遞迴後，雖然不再使用系統的函式遞迴，但仍需要處理與原本遞迴相同數量的運算，因此時間複雜度仍可視為：

```math
O(T(m,n))
```

其中 `T(m,n)` 表示計算阿克曼函數所需的運算次數。

空間方面，程式使用大小為 `10000` 的整數陣列作為 Stack，因此在程式實作中配置的陣列空間為：

```math
O(10000)=O(1)
```

但實際所需的 Stack 空間會隨著阿克曼函數的計算過程而增加，因此若不考慮固定陣列大小，其空間需求可表示為：

```math
O(D(m,n))
```

其中 `D(m,n)` 表示計算過程中 Stack 所需的最大深度。

# 二、冪集

## 1. 解題說明

本題要求我們使用遞迴的方式實作 Powerset，也就是求一個集合的所有可能子集合。

如果集合 S 有 n 個元素，則每一個元素都有「選擇加入子集合」或「不加入子集合」兩種可能，因此總共有：

```math
2^n
```

個子集合。

例如：

```math
S=\{a,b,c\}
```

則 Powerset 為：

```math
P(S)=\{\emptyset,\{a\},\{b\},\{c\},\{a,b\},\{a,c\},\{b,c\},\{a,b,c\}\}
```

本題可以利用遞迴來處理每一個元素。

對於目前的元素，有兩種選擇：

1. 不將目前元素加入子集合。
2. 將目前元素加入子集合。

當所有元素都處理完後，目前的子集合就是 Powerset 中的一個結果。

因此可以利用遞迴不斷處理下一個元素，直到所有元素都完成選擇。

### 1.1 範例

以：

```math
S=\{a,b,c\}
```

為例。

首先處理 `a`，有兩種可能：

```text
{}
{a}
```

接著處理 `b`：

```text
{}
{b}
{a}
{a,b}
```

最後處理 `c`：

```text
{}
{c}
{b}
{b,c}
{a}
{a,c}
{a,b}
{a,b,c}
```

因此最後可以得到：

```math
P(S)=\{\emptyset,\{c\},\{b\},\{b,c\},\{a\},\{a,c\},\{a,b\},\{a,b,c\}\}
```

雖然輸出的順序可能不同，但只要包含全部的子集合，就是正確的 Powerset。

---

## 2. Algorithm Design & Programming

本題的演算法是利用遞迴處理集合中的每一個元素。

1. 如果 `index == n`，代表所有元素都已經處理完成，輸出目前的子集合。
2. 不選擇 `S[index]`，繼續處理下一個元素。
3. 選擇 `S[index]`，將它加入 `current` 後，繼續處理下一個元素。

因此每一個元素都會產生兩種可能，最後產生：

```math
2^n
```

個子集合。

```cpp
#include <iostream>
using namespace std;

void powerset(char S[], int n, int index, char current[], int size)
{
    if (index == n)
    {
        cout << "{ ";

        for (int i = 0; i < size; i++)
            cout << current[i] << " ";

        cout << "}" << endl;
        return;
    }

    // do not select S[index]
    powerset(S, n, index + 1, current, size);

    // select S[index]
    current[size] = S[index];
    powerset(S, n, index + 1, current, size + 1);
}

int main()
{
    char S[] = {'a', 'b', 'c'};
    char current[3];

    powerset(S, 3, 0, current, 0);

    return 0;
}
```

執行結果：

```text
{ }
{ c }
{ b }
{ b c }
{ a }
{ a c }
{ a b }
{ a b c }
```

---

## 3. 效能分析 (Analysis)

### 3.1 時間複雜度（Time Complexity）

每一個元素都有兩種選擇：

```text
選擇
不選擇
```

因此 n 個元素會產生：

```math
2^n
```

種不同的子集合。

遞迴函式本身會形成一棵二元遞迴樹，因此遞迴呼叫的數量會隨著 n 增加而快速增加。

如果只考慮產生所有子集合的遞迴結構，時間複雜度為：

```math
O(2^n)
```

但是本程式在每一個子集合產生後，還需要使用迴圈將子集合中的元素輸出。

每個子集合最多包含 n 個元素，因此如果將輸出成本也計算進去，完整的時間複雜度為：

```math
O(n2^n)
```

因此本題若考慮實際輸出結果，時間複雜度為：

```math
O(n2^n)
```

### 3.2 空間複雜度（Space Complexity）

程式使用 `current[]` 儲存目前正在建立的子集合。

最多需要儲存 n 個元素。

此外，遞迴的最大深度也是 n。

因此空間複雜度為：

```math
O(n)
```

## 5. 效能量測（Measuring）

### 5.1 量測方法

可以使用 C++ 的 `chrono` 進行量測。

在呼叫 `powerset()` 函式之前記錄開始時間，函式執行完成後記錄結束時間，最後計算兩個時間點的差值，即可得到程式的執行時間。

由於 Powerset 的子集合數量會隨著 n 增加而快速增加，因此可以使用不同大小的集合進行測試，觀察執行時間的變化。

|---|---:|---:|---:|

| 三 | 15 | 32768 | 14319ms |

```math

```

計算得到。

實際執行時間會受到電腦硬體、編譯器最佳化以及輸出速度等因素影響，因此應以實際執行程式後的 `chrono` 測量結果為準。

### 5.3 量測結果分析

從 Powerset 的特性可以看到，當 n 增加時，子集合數量會快速增加。

例如：

```math
2^5=32
```

而：

```math
2^{10}=1024
```

當 n 從 5 增加到 10 時，子集合數量就從 32 增加到 1024。

如果 n 增加到 20：

```math
2^{20}=1048576
```

此時就已經需要產生超過一百萬個子集合。

因此可以觀察到 Powerset 的計算量會隨著 n 以指數方式增加。

另外，本程式還需要將每個子集合中的元素輸出，因此實際輸出所需要的時間會比單純產生遞迴結構更高。

這也可以對應到前面的時間複雜度分析。若只考慮遞迴產生的所有可能性，可以表示為 `O(2^n)`；若將每個子集合的輸出成本也計算進去，則為 `O(n2^n)`。
